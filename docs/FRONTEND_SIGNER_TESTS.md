# Desktop and signer command evidence

The current owner instruction replaces encrypted portable backup creation/verification with a written BIP39 recovery phrase. After native password entry, the Go signer displays the generated phrase and asks for recorded words. Successful confirmation enables the wallet. Restoring an empty installation accepts the known phrase, an app password and any explicitly used BIP39 passphrase in native Go inputs. Electron never receives a phrase, password, passphrase, seed or private key.

The desktop exposes fixed public operations, a read-only `getVersion()` and a value-free `onLocked(callback)`. The encrypted-file `backup` and `restore` operations are absent from validation, preload and renderer. Phrase restoration uses `import:{words:12}` to trigger the native import surface; its actual phrase length/checksum is validated in Go. The empty object `confirmRecovery:{}` resumes pending setup after native password reauthentication. The bridge has no word-confirmation, reveal or export payload. A confirmed wallet hides further setup actions, and their handlers cannot request another disclosure. Go independently decides whether disclosure or payment authorization is allowed.

The first screen uses the signer's explicit storage state. Only confirmed `missing` storage with `walletExists:false` offers creation and **Restore from recovery phrase**; `present` offers unlock, while `unavailable` offers a storage retry. No credential dialog opens automatically. Create sends only `{words:12}` or the explicit advanced `{words:24}` and suppresses duplicate native credential requests. A durable root whose native phrase display or confirmation was cancelled remains pending; it is not replaced by a new root. The current public snapshot supplies only `recoveryConfirmed`, never the phrase or recorded words. `false`, missing and malformed confirmation values stay pending on both mainnet and testnet. Historical `backupVerified:true` cannot enable the new flow.

Pending setup offers **Finish recovery phrase setup** in the overview, Settings and Send. Send opens its form, while preparation remains disabled until confirmation. The native setup continuation preserves the selected token and exact recipient/amount/memo only for its unchanged wallet and form; it never prepares or sends automatically. Receive opens public setup guidance and continues to the authoritative native QR only after confirmation and only for its original unchanged wallet/view/session. Cancelled or incomplete confirmation, navigation, closing a tab, lock and delayed account refresh cannot revive an abandoned receive request. Once confirmation succeeds, receive/copy/QR saving and preparation become available in every profile. Later account metadata refreshes retain confirmed eligibility rather than requiring another phrase disclosure.

Each deterministic account index has a top account tab: zero is Main account and later indices retain their original Account N labels. Its table contains Network, Assets, Native balance and Receive address columns. Source-bound registry fixtures cover all nine mainnet networks and eleven asset identities, plus twelve explicit testnet/local networks and fourteen assets. These public account DTO fixtures establish UI scope, not native derivation or network transaction acceptance. Clicking a row or its network button opens a wallet; Enter and Space activate focused rows. Copy captures the account ID, calls native verified copy and does not open a tab. Editing rendered addresses or row metadata cannot substitute copied contents. Addresses remain single-line with an ellipsis and full tooltip.

Opening a wallet shows only its own balance, asset selector, address, network details and Send/Receive controls. Send stays hidden until requested. Closing its form clears the local draft and discards delayed preparation/scan replies without cancelling durable reservations. Middle-click or Delete closes wallet tabs while account tabs remain. Closing an inactive wallet preserves the active form, focus and in-flight view replies. Closing the active wallet returns to its account table. Native receive responses can update their own committed public descriptor after navigation, including Decred's issued address, but cannot populate another wallet or survive a lock.

Overview native balances use exact atomic decimal strings and pinned asset precision. Base/Horizen show ETH; HyperEVM and HyperCore retain separate HYPE observations. Missing, duplicated, malformed, stale, incomplete and failed observations remain unknown or unavailable. The queue sends one background balance request at a time, once per visible account descriptor and provider configuration; explicit Refresh balances supersedes stale work. Native credential/authorization actions and receive guidance pause new background work, including after the native action's tab closes. Metadata refresh stays inside that pause. Success, cancellation and failure resume scheduling through cleanup, while lock clears queued work. These public queries disclose addresses to configured providers and never reset inactivity.

Settings contains creation/restoration/unlock, pending recovery setup, password change, account addition, bounded index recovery and the Local payment journal. The modal traps keyboard focus, makes background content inert and returns focus on Escape, Close or backdrop dismissal. Native credential actions close it. Journal wallet/asset selectors are independent of Send intent. Filtering uses exact account/network/asset identities, reconciliation keeps the original operation identity and cancellation is available only for unsigned PREPARED entries. Changing journal context discards stale results/errors without releasing reservations or overwriting a different payment preview. Named/rotated association has its own public address field independent of Send.

Receive remains the Go-owned network/address/QR verification surface. The signer supplies its exact public copy target independently of display text. Copy address deliberately copies and keeps the window open; Done does not copy automatically, and cancelling after an explicit copy does not undo that public clipboard action. The body scrolls separately from action buttons; only its displayed QR is resized while the original saved PNG remains unchanged. Electron embeds no duplicate receive QR.

Lock, suspend, shutdown, explicit lock, core failure and locked status clear cached accounts/tabs, assets, amounts, recipient/memo, balances, history, diagnostics, discovery/association fields, prepared preview, Settings, setup guidance, journal context and queued balance work. Session/view generations discard delayed replies. Idle status polling never emits activity. Native requests have a six-minute response deadline renewed only by a valid current value-free native activity frame; Go's independent inactivity policy remains authoritative.

Expected operation errors cross the bridge as reviewed value-free constants. Credential policy/mismatch, oversized input, invalid mnemonic and cancellation have fixed guidance; unknown/raw errors become `REQUEST_FAILED_STATE_UNKNOWN`. Encrypted-file failure codes no longer belong to the current public flow. Ordinary failures resolve the main IPC handler through a strict `{ok:false,error:code}` envelope, avoiding handler stack logging; untrusted frames and invalid request schemas remain rejected before core admission. Renderer errors use fixed inert text in a focused alert, persist across redundant locked polls, clear on an explicit action and never retry a payment automatically.

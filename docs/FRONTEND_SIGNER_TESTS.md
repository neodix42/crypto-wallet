# Desktop and signer command evidence

Observed on 2026-10-23 with the repository's pinned Go, Node, Electron, TypeScript, jsdom and c8 dependencies. All credential fixtures are public test values, including the published BIP39 zero-entropy example. These tests never submit a transaction or access real user secrets.

The desktop exposes fixed public operations, a read-only `getVersion()` and a value-free `onLocked(callback)`. Version metadata comes from Electron's packaged application version through a separate origin-checked IPC handler. The renderer cannot choose an IPC channel or access native event objects. OS lock, suspend, shutdown, explicit lock, core failure and locked status notifications clear account and wallet tabs, cached accounts, assets, amounts, recipient, memo, balances, history, diagnostics, Decred discovery controls, the association address and the prepared plan. They also hide Send and close Settings. Status polling runs every five seconds only while no request is pending; it never emits activity. Balance, chain-history, journal and payment-preview replies are bound to the current view generation. Closing an active wallet or Send form invalidates delayed form replies. Closing an inactive tab preserves the active wallet's work and input focus. Successful native receive results can update their own committed public descriptor after navigation, including Decred's issued address, but cannot populate a different wallet's page or survive a lock. Credential actions and their global account refresh likewise use the session generation: navigating tabs while an encrypted backup completes still refreshes its verified state, while a lock invalidates that refresh. Native-capable requests have a six-minute transport deadline; the Go coordinator enforces the five-minute inactivity lock. A current, value-free native activity frame renews only its existing request deadline. It never resolves that request or manufactures background activity. Non-native, stale, malformed or excessive activity fails closed.

Expected operation failures now follow a closed, value-free code path from the signer through private IPC, core and the desktop bridge. Password policy/mismatch, oversized native input, invalid BIP39 phrases, backup destination/conflict/write/verification failures, unsafe restore sources and cancellation have fixed guidance; unknown errors become `REQUEST_FAILED_STATE_UNKNOWN`. Known credential-validation and backup/restore failures display a fixed notice in the native Go window before the final response; cancellation and unknown categories do not open an additional notice. Its wording contains no password, phrase, selected path, provider text or raw operating-system error. The desktop main handler returns an `{ok:false,error:code}` envelope for ordinary operation failures, so those failures do not reject `ipcMain.handle` and produce Electron handler stack spam. Untrusted frames and invalid public request schemas remain rejected before core admission.

The preload validates the exact envelope and throws only a safe constant as `Error.message`. [Electron contextBridge drops custom error properties](https://www.electronjs.org/docs/latest/api/context-bridge#parameter--error--return-type-support), so the renderer matches the exact allowlisted message rather than relying on a custom `code` field. It renders fixed text in a sticky, focused `role="alert"` banner, preserving guidance across redundant locked-status notifications while already locked. A new explicit action clears the banner; an actual transition from an unlocked wallet clears it with the cached view. Delayed failures from an invalidated session cannot overwrite the locked view. No failure automatically retries creation, backup or a payment.

Hidden accounts retain their original derivation indices and can be shown and unhidden. Explicit inclusive recovery ranges reconstruct at most twenty groups through the signer. Decred's birthday, gap, address limit and block budget load from the selected account's saved public parameters on every selection. Missing or out-of-range values use documented bounded defaults; the block budget is limited to two million and zero selects the backend default. A two-account regression proves that edited values from one account cannot become another account's discovery settings. Locking blanks these fields. Editing a preview or changing tabs clears the visible plan and disables confirmation without cancelling its durable reservation. A PREPARED journal row offers explicit cancellation of that original unsigned identity. Signed, awaiting-confirmation and submitted identities have no such cancellation control. No tab, asset change, RPC response or failure automatically sends, retries or cancels a payment.

The first screen uses the signer's explicit vault state. Only confirmed `missing` storage with `walletExists:false` offers creation/restoration; `present` offers unlock, and `unavailable` offers a storage retry. No credential dialog opens automatically. The explicit Create app password action sends `{words:12}` to the native signer and suppresses duplicate credential requests while it is pending. The renderer never receives the generated root or password. The default launcher profile is mainnet; testnet requires an explicit separate profile. Before the snapshot arrives, the badge says that the profile is being checked. It then displays only the trusted snapshot's known mainnet/testnet value, independently of the release-status link. Mainnet connectivity does not assert production readiness.

Each deterministic index has a top account tab: index zero is Main account, with later indices retaining their original Account N labels. The active account page lists every returned network wallet for that index in a table with Network, Assets and Receive address columns. Clicking a row or its network button opens that wallet; Enter and Space activate a focused row. The nested copy button does not open the wallet. Source-bound public registry fixtures cover all nine mainnet networks and eleven asset identities, plus the explicit testnet/local profile's twelve networks and fourteen assets. These synthetic account DTO tests establish the UI list and scope, not native derivation or network transaction acceptance. Row addresses stay on one line with ellipsis and a full-address tooltip. Every row has a labeled copy icon. Copying sends only the captured account ID to the native Go receive-verification flow; editing the displayed address or row metadata cannot substitute clipboard contents. Decred copy/QR saving refreshes the committed receive descriptor without changing tabs or clearing a payment form.

Opening a wallet adds or selects that network wallet's own top tab and displays its balance, asset selector, public address, Send and Receive controls, journal and network details. It queries real backend balance/history operations for the selected account; merely listing rows does not query every address. Middle-click or Delete closes an opened wallet tab. Deterministic account tabs remain available; closing the active wallet returns to its account overview and clears visible payment intent without cancelling durable reservations. Opening or selecting a wallet keeps Send hidden until the user chooses Send. Closing the form clears its inputs and preview, disables confirmation and drops delayed preparation/scan replies. Hidden Send controls cannot prepare, scan or send through their handlers. NEAR/Aptos association uses a separate public address field under network details, independent of the transfer form. Balance display formats decimal strings of atomic integers using the pinned asset decimals, including values beyond JavaScript Number precision. Base/Horizen ETH and ZEN use separate asset IDs and balances; selected ZEN also shows its separate ETH gas balance. Missing, malformed and failed responses remain explicitly unknown or unavailable, never an invented zero. Decred without a configured authenticated TLS node displays a connection-required message.

The top-right Settings button contains the former Wallet menu, including creation/import/restore, backup, password change and deterministic-account recovery. Its modal panel traps keyboard focus, makes the background inert and restores focus on Close, Escape or a backdrop click. Lock and native-action handoff close it. Only actions appropriate to the current vault state are visible.

Receive opens the Go-owned verification window with the complete network/address, a local QR and a Copy address button. The signer derives and validates the address independently of renderer input, and supplies the exact address separately from its display summary. Copy requires its native button, leaves the window open and gives feedback; Done alone does not copy. Deliberately copying and then cancelling does not undo the public clipboard operation. The body scrolls separately from the action buttons; only the displayed QR is resized to 320 pixels, while the original 512-pixel PNG remains unchanged for saving and verification. Electron no longer embeds a second receive QR.

The local journal filters by exact `plan.account.id`, network and selected asset. Identical EVM addresses on different networks do not merge operations. To find or cancel a reservation for another asset, select that original asset; filtering never deletes the reservation. Unknown or foreign account descriptors provide no reconciliation/cancellation controls. Signed and submitted operations retain their original identity for reconciliation, and no automatic replacement payment is created.

Before mainnet backup verification, row copying, Receive, QR saving and payment preparation are disabled with visible backup guidance. Go independently enforces the required security gate. After verification, the UI enables those controls even if the user navigated tabs while the native backup dialog was open. Recovery requires the encrypted backup and its password; no phrase reveal or password reset exists.

Reproduce from the repository root:

```sh
./scripts/with-toolchain.sh npm --prefix desktop run check
./scripts/with-toolchain.sh node --check desktop/ui/renderer.js
./scripts/with-toolchain.sh python3 scripts/frontend-coverage.py
./scripts/with-toolchain.sh python3 scripts/go-coverage.py
./scripts/with-go.sh python3 desktop/tests/generate-registry-fixture.py # only after a reviewed registry change
./scripts/with-go.sh go test -race ./cmd/wallet-signer -count=1 -timeout=90s -coverprofile=/tmp/wallet-signer-main-race.cover
./scripts/with-go.sh go tool cover -func=/tmp/wallet-signer-main-race.cover
./scripts/with-go.sh go vet ./cmd/wallet-signer
```

The signer tests reuse an explicitly supplied private `:18x` display or start a test-only Xvfb from PATH or `.tools/xvfb/root/usr/bin/Xvfb`. They never attach to the desktop user's `:0` display. The server lives until the test process finishes because GTK retains its display connection between tests. If no isolated display is available, the relevant tests explicitly report `NOT_RUN` as skips; that is not native acceptance and the lost coverage remains visible. Legal test KDF parameters are 64 MiB, three passes and four lanes; the production default and format's minimum checks remain unchanged.

The current frontend evidence is `reports/wallet-layout-frontend.log`, `reports/frontend-coverage.json` and `reports/desktop/coverage-summary.json`. All 53 tests passed with no skips. Main/preload/validation/codec have 100% statement and branch coverage; renderer has 100% statements and 98.77% branches. Every shipped JS file remains included and the original per-file floors remain enforced. This run uses the actual bundled HTML/JS in jsdom and compiled main/preload code with Electron API doubles. It does not establish packaged native dialogs, sandbox behavior, a clean OS matrix, live RPC acceptance or mainnet transaction acceptance; those need separately source/artifact-bound evidence.

# Electron interface and signer evidence

The current owner instruction uses Electron for every wallet dialog. Go still generates the BIP39 root, validates restoration and recorded words, encrypts storage, reconstructs transaction effects and signs. Passwords, imported phrases and challenge words enter a separate Electron prompt window; the generated phrase travels to that window only for recording. This is an explicit change from the former native-only policy. The dedicated Electron prompt renderer is now inside the secret-handling and approval trust boundary. A compromised prompt renderer can observe its displayed secrets or falsify a click; Go generation alone does not prevent that. This change is not an independent security audit or a production-readiness claim.

The normal portfolio preload retains fixed public operations, read-only `getVersion()` and value-free `onLocked(callback)`. It has no credentials, phrase response, arbitrary signing, file-backup/export or generic IPC methods. The owner-authorized empty `backupPhrase:{}` request asks Go for explicit confirmation and current-password verification; only its isolated `recoveryBackup` prompt can receive numbered words, while ordinary results remain public. Create carries only `{words:12}` or the explicit `{words:24}`; import carries word-count configuration, with actual phrase length/checksum verified in Go. Pending recovery resumes through `confirmRecovery:{}` after password reauthentication. Public snapshots contain `recoveryConfirmed`, never words or credentials. Old `backupVerified:true` does not authorize the new flow. Encrypted portable backup creation, verification and file restoration remain removed.

The private transport uses an interim `prompt` frame correlated to the original operation ID/session and a fresh 32-hex prompt ID. Main validates kind-specific fields and limits, then opens a sandboxed modal at the separate `wallet://prompt/` origin with a fresh nonpersistent partition, disabled cache, denied permissions/network/navigation/popups/webviews/downloads, context isolation and no Node or developer tools. Its separate preload exposes only `getPrompt`, `respond` and public receive `copyAddress`. Delivery and replies require that exact live window, main frame, origin, operation and prompt ID. IDs are single-use and bounded per operation. The portfolio renderer cannot get or answer a prompt. A validated `promptReply` returns through the existing private Go transport without granting a regular public operation access to secrets.

Go checks the recorded words separately after the recording acknowledgment; a click alone cannot enable the wallet. Input sizes use UTF-8 byte bounds. Wrong words, cancellation and failed persistence leave the same durable root pending. A confirmed root cannot be redisplayed through setup. Phrase restoration reproduces canonical accounts with the same or a different local app password; an original optional BIP39 passphrase remains a separate recovery requirement. The local password is never substituted for it.

Prompt content uses inert text and bounded local PNG data. Secret inputs are masked; phrase recording disables selection/copy. Submit, cancellation, page hiding and unload clear sensitive DOM values. Main releases prompt payloads, clears framed buffers where possible, destroys the modal and clears its session. Lock, locked status from another request, OS lifecycle events, navigation, renderer crash, timeout, core EOF and final operation completion invalidate a live prompt. JavaScript/runtime/OS copies cannot be guaranteed erased; strings may remain until garbage collection. No prompt payload is intentionally written to logs, browser storage, files, crash uploads, clipboard or network. Public address copying and QR-file selection are handled in main from signer-provided data; the renderer supplies neither arbitrary clipboard text nor filesystem paths.

The dialog's native title stays bound to the Go operation. The BrowserWindow title-change handler prevents document-title replacement, and main sets the fixed title after loading and before showing it. Tests simulate Chromium's default title replacement, in addition to testing strict sender, stale callback and cleanup behavior. Screenshot automation rejects secret/dialog windows and never saves a generated phrase.

The first screen distinguishes missing, present and unavailable storage; it never initializes over unreadable data. Pending setup is actionable in the overview, Settings and Send. Send opens its form but preparation remains gated; completing setup preserves a draft only for its unchanged wallet/form and never sends automatically. Receive continues after successful setup only for its original unchanged wallet/view/session. Navigation, cancellation, tab closing and lock discard abandoned continuations.

The overview retains account tabs and semantic wallet rows for all nine mainnet networks/eleven assets, plus the explicit twelve-network/fourteen-asset test/local profile. Row click/Enter/Space opens its wallet tab; the copy icon captures the trusted account ID rather than edited DOM address text. Addresses stay single-line with a full tooltip. Native balances use exact atomic strings, distinct ledger identities and one background request at a time; missing, duplicated, malformed, stale or failed results remain unknown/unavailable. Credential and authorization actions pause new background work through metadata refresh. Public queries disclose addresses to configured providers and do not renew inactivity.

Wallet tabs show their own balances, assets and network details. Send appears only on request. Closing a form/tab clears its draft and rejects late results without cancelling durable preparations or releasing reservations. Middle-click/Delete closes wallet tabs while account tabs remain. Settings contains recovery, password/account actions and an independent Local payment journal. Its filtering and reconciliation retain exact original identities without overwriting Send intent. Receive displays the Go-validated network/address/QR in the isolated Electron dialog. Copy deliberately copies the separately supplied address and keeps the window open; Done does not copy, and cancellation does not undo a deliberate public copy.

Lock clears portfolio caches, drafts, previews, diagnostics, Settings, journal context and queued balances. The dialog's actual keyboard events and trusted pointer events are throttled and renew the original request deadline plus Go's existing activity policy. Background polling/programmatic input is not activity. The six-minute response deadline does not replace Go's independent five-minute inactivity lock. Expected operation errors use fixed reviewed codes; raw errors and payloads never become user-visible exception text or automatic payment retries.

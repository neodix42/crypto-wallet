# Wallet table, settings and receive/send interactions

The overview uses a semantic wallet table with Network, Assets, Native balance and Receive address columns. A primary click on a row opens that wallet's tab; Enter or Space works on a focused row. The separate copy-icon button uses the native verified-copy flow and does not open the row. Addresses stay on one line with an ellipsis and full tooltip. Each visible wallet's native balance is queried once for its current account descriptor and network configuration, with one background request at a time. Refresh balances requests a new observation. Base and Horizen show ETH; HyperEVM and HyperCore retain separate HYPE balances. Integer-string formatting preserves exact precision. Missing, malformed, incomplete and failed observations remain unknown or unavailable, never a fabricated zero.

Wallet tabs initially show balances and network details. Send reveals that wallet's payment form even before mainnet backup verification; preparation and signing remain gated. Its inline backup action preserves the selected asset, recipient, amount and memo when the original wallet and form remain unchanged. It never prepares or sends automatically. A global account refresh can clear local drafts after navigation; durable journal entries remain intact. Close send form clears its local draft and invalidates pending view replies. Closing a form or wallet tab never cancels a durable preparation, broadcasts, retries or releases a reservation. Middle-click or Delete closes an opened wallet tab; deterministic account-group tabs remain. Closing an inactive wallet preserves the active wallet's form, focus and pending replies. Closing the active wallet returns to its account table and discards late view results.

Receive remains clickable before mainnet backup verification. It first opens public backup guidance with an explicit action to create and verify an encrypted backup in Go. Successful verification continues to the authoritative QR window only for the original unchanged wallet, view and session. Cancelling, failing verification, closing the wallet, navigating away or locking cannot resume an abandoned flow. Once verified, Receive opens the authoritative Go window with its QR code, full independently derived address and an explicit Copy address button. Copying keeps the window open and shows confirmation; Done does not copy automatically. The exact clipboard value is passed separately from the display summary by the signer. There is no duplicate QR embedded in the wallet page. Decred advances and durably saves its receive descriptor once before displaying it; a successful reply updates that descriptor across view changes while lock invalidates the old session. Mainnet backup requirements remain enforced in Go.

The top-right Settings button contains the former sidebar's create/import/unlock, backup/restore, password change, additional-account and recovery-range actions, plus the Local payment journal. The journal has independent wallet and asset selectors, so it is usable from the account overview without changing the active Send draft. Reconciliation results stay inside Settings. Cancelling an unsigned preparation clears a visible plan only when its operation ID matches; neither action overwrites another payment's preview. Journal context changes discard delayed results and errors, and lock clears the selectors and results. The opaque Settings modal makes the background inert and traps keyboard focus, including its selects. Escape, Close or the backdrop dismisses it and returns focus. Credential actions close the panel before opening the existing native input window. Named/rotated account association has its own public-address field in wallet diagnostics, so it does not depend on the hidden send form.

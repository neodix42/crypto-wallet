## Constraints requiring explicit review, not fictitious completion

The phrase restores canonical keys, not missing journal entries, exchange credentials/operation history, named/rotated associations, RPC credentials or Decred discovery counters. Existing recovery controls and reconciliation procedures must be validated without reintroducing the removed encrypted-backup workflow. Bounded histories are not exhaustive archival recovery. Unsupported agent/vault/unified HyperCore authorities remain rejected. The owner's Bybit-only spot extension is the explicit exception to the original v1 trading exclusion; it grants no HyperCore trading authority.

Some chains cannot encode an absolute signed ceiling for every fee component; the current reserve/estimate disclosures need review and network acceptance. Whole-directory rollback, compromised trusted Electron/OS/display components and complete erasure of runtime copies remain documented limits. Production acceptance requires an honest supported scope and review of these limits, not claims that tests remove them. See [recovery](RECOVERY.md), [EVM/Core](EVM_CORE.md), [DCR/TON](DCR_TON.md) and [threat model](THREAT_MODEL.md).

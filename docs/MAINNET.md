# Mainnet connections and profile selection

The desktop starts in the **Mainnet** profile. Run `./cryptowallet --profile=testnet` when deliberately using test/local networks. Profiles have separate vaults under `$XDG_CONFIG_HOME/cryptowallet/mainnet` and `$XDG_CONFIG_HOME/cryptowallet/testnet` (default `~/.config/cryptowallet/...`). Starting mainnet does not convert, copy or relabel an existing testnet vault. Phrase restoration explicitly selects a destination profile; the words do not carry local profile settings.

One root derives the initial account for every supported mainnet network. Network identity remains part of each wallet: HyperCore and HyperEVM have separate balances, and the same EVM address on Ethereum and Base does not move assets between them. Generated and pending wallets require native recovery-phrase recording/confirmation before receive or send on either profile. This replaces the former encrypted-file backup prerequisite; the app no longer creates, verifies or restores those files. See [current phrase recovery](PHRASE_RECOVERY.md). Credentials and transaction approval remain in the isolated native signer.

## Configured providers

These public endpoints require no preinstalled development tools or bundled API credentials. They can rate limit, censor, change availability or provide incorrect data. A matching network identifier is a necessary check, not a consensus proof. Querying a wallet exposes its public address to its selected provider. Prefer a provider you trust or a node you operate for sustained use; no uptime or capacity guarantee is inferred from one successful request.

## Changing a provider

Open the wallet and choose **Configure trusted RPC**. Enter the endpoint and any supported credentials in the native window, then approve the stated provider trust/privacy implications. Settings are encrypted in the local vault. A phrase-restored installation must configure its own provider settings; the words do not contain RPC credentials. Never put credentials in a URL, command line, issue, screenshot or log.

The optional API key field is used by the TON adapter. Decred uses its username and password fields. Other current adapters use the configured URL; they do not support arbitrary authentication headers. A provider requiring unsupported authentication needs an appropriate trusted local gateway or a future reviewed adapter extension. The wallet does not invent credentials, disable certificate verification or silently switch to another provider on failure.

TON Center permits one request per second without an API key and documents [rate limits](https://docs.ton.org/api/rate-limit) and [authentication](https://docs.ton.org/api/v2/authentication). NEAR publishes provider-specific limits in its [provider list](https://docs.near.org/api/rpc/providers). A failed, stale or incomplete query must remain unavailable/unknown; it must not appear as a confirmed zero balance. Do not stress test shared public endpoints.

For a canonical NEAR implicit account that has not been created on chain, the wallet now distinguishes verified absence from a connection failure: it displays `0 NEAR` with `NOT_CREATED (final state)` only after a fresh final-block query and a structured `UNKNOWN_ACCOUNT` response matching that exact account, block height and hash. Existing accounts still require the expected full-access key. Named accounts, missing/revoked keys, malformed replies and transport failures never become an inferred zero. The default remains `https://rpc.mainnet.near.org`; this change does not migrate saved endpoints or switch providers automatically. See [balance behavior and evidence](BALANCE_CONNECTIVITY.md).

## Decred trusted-node setup

Decred has no public default RPC. Until configured, its overview row and wallet page say **Connection required**, with authenticated-TLS setup and unknown-balance guidance on hover. The interface skips balance RPC requests in that state. A configured endpoint is not proof of successful connectivity or a complete scan; failures still leave the balance unknown.

This adapter scans full blocks from an authenticated trusted `dcrd`; it does not independently verify consensus through SPV. No `dcrwallet`, recovery-phrase import into a node or second secret store is needed. Follow the official [node setup](https://docs.decred.org/wallets/cli/dcrd-setup/) and [RPC options](https://docs.decred.org/wallets/cli/dcrd-and-dcrwallet-cli-arguments/):

1. Run a synchronized **mainnet** node without testnet/simnet options. Keep its RPC listener private; the usual mainnet `dcrd` RPC port is **9109**, not `dcrwallet`'s 9110. Configure unique username/password credentials in the protected node configuration file, not command-line arguments. HTTP Basic authentication is supported; client-certificate authentication is not. Limited RPC credentials suffice for balance queries according to the [official method table](https://github.com/decred/dcrd/blob/master/docs/json_rpc_api.mediawiki).
2. Use TLS with a certificate matching the endpoint hostname and trusted by the operating system. Stock local `dcrd` commonly generates a self-signed certificate, and the wallet has no custom-CA upload field. Deliberately install the operator's verified CA/certificate into the OS trust store or use a trusted local TLS gateway, then restart the wallet. Do not disable TLS or certificate verification.
3. In the Decred wallet, choose **Configure trusted RPC**, enter the node's `https://` URL, username and password in the isolated private wallet dialog, and approve the provider trust/privacy details. For a local node the URL is commonly `https://localhost:9109`, provided its certificate matches `localhost`. The optional API-key field is unused for DCR. Endpoint settings are encrypted and are not recovered from the phrase.
4. Open **Network details & public diagnostics**, set and confirm the birthday, address gap, address limit and block budget for that wallet, then refresh its balance. Defaults are birthday **0**, gap **20**, **1,000 addresses per branch** and **10,000 blocks**. A block budget of `0` selects that same default. Allowed gap is 1–100, address limit is between the gap and 10,000 per branch, and the block-budget ceiling is **2,000,000**. The default cannot scan mainnet from genesis. A restored phrase may control older payments and later address indices; do not choose a recent birthday to bypass that history. A recent birthday is appropriate only for a root known to have been newly generated then.

Each scan is recomputed with sequential block requests, under the coordinator's **30-second** balance-query deadline. Increasing the budget alone does not make full historical mainnet synchronization practical; persisted incremental synchronization remains deferred. An incomplete scan never proves an empty wallet. The displayed balance counts ordinary confirmed spendable DCR; immature outputs and unsupported staking/mixing scripts are excluded. See [DCR/TON limitations](DCR_TON.md). Balance scanning does not require `txindex`, but the current send/reconciliation path uses `getrawtransaction` for mined transactions, so enable the [node's transaction index](https://github.com/decred/dcrd/blob/master/doc.go) for that functionality. No new Decred synchronization feature or live-node acceptance is claimed by the balance-message change.

## Executed evidence and remaining gates

The historical [read-only probe report](evidence/mainnet-rpc.json), 2026-10-23: **29 PASS**, **1 BLOCKED**, **0 FAIL**. Eight public mainnet domains returned their expected identities. Required EVM priority-fee calls, both rollup fee-oracle methods, canonical ZEN runtime hashes/decimals, NEAR transfer protocol fields, Aptos gas estimation and TON zerostate matched the adapter's public requirements. The older Aptos fullnode alias also responded, but the default uses the current documented API host. Decred connectivity is **BLOCKED** because no authorized authenticated mainnet node was configured. No user profile, wallet address, balance, secret or signed transaction was read or transmitted by these probes, and nothing was broadcast.

These retained checks establish provider connectivity and selected public metadata only for their recorded run. They do not certify the subsequently changed recovery policy or rebuild. Funded mainnet transfers were **NOT_RUN**. Required public testnet acceptance, identified external-wallet interoperability, complete installed OS/recovery testing, 24-hour stress work and independent security review retain their existing incomplete statuses in [STATUS](STATUS.md). Selecting mainnet does not mark those release gates passed.

# Electron interface and prompt evidence

Owner instruction on 2026-10-24 replaces every Go-owned application window with Electron. Go still generates the random BIP39 root, encrypts storage, validates imported words/passwords, checks recorded words, derives accounts, independently validates transactions and signs. The shipped signer has no GTK/UI dependency or display-server initialization. Retained GTK source/tests are non-shipped legacy regressions, not a fallback or evidence for the new interface.

The ordinary portfolio remains at `wallet://app/` with its public-only preload. Each signer-authored dialog uses `wallet://prompt/`, its own preload, sandbox, context isolation and a fresh nonpersistent session. Password/import/challenge fields are masked. Phrase recording and the owner-authorized authenticated backup display are nonselectable and offer no copy, QR, print or file operation. Settings → Wallet → Back up recovery phrase requires explicit confirmation and current app-password verification in Go for every view; its separate `recoveryBackup` prompt shows numbered words with a Done button and does not repeat the setup challenge or mutate vault state. Inputs/phrase DOM clear before a reply; closing, hiding, lock, navigation, crash, timeout and transport failure revoke the dialog. Public Receive shows the Go-provided network, QR and single-line address; copying uses main's stored verified address rather than a renderer argument. Electron also owns the file pickers.

This changes the trust boundary. The Go coordinator/supervisor transient relay, Electron main and dedicated prompt renderer/preload can contain entered passwords/phrases and generated phrase text. They must never log or persist it. An attacker controlling those trusted components can capture secrets or spoof the display; Go generation does not prevent that. Ordinary wallet operations/snapshots, RPC payloads, clipboard and QR remain secret-free. Entropy, binary seeds, private/extended keys and vault keys remain in Go. Go/JSON/V8/Chromium copies cannot all be guaranteed erased.

Prompt/reply transport uses inherited bounded pipes. Replies are bound to the original request/session/epoch and a random single-use signer prompt ID; unsolicited, stale, duplicate, replayed, malformed, wrong-kind and cross-window/frame/origin replies fail closed. A recording click alone grants no authority: Go separately compares the three supplied words. All existing recovery, transaction digest, fee, reservation, per-send password and lock checks remain in Go.

The coordinator now sets and verifies zero soft/hard core limits and non-dumpability before receiving prompts while retaining RPC networking. Tests exercise successful actual loopback communication and startup/protection failures in owned subprocesses. The signer retains its separate IP isolation and dump checks. Electron inherits the launcher's zero core-size limit; post-exec Electron non-dumpability is not guaranteed. Exec can reset dumpability and system-managed piped core handlers can ignore the limit. Host crash collection and privileged memory extraction remain limitations, not passed erasure guarantees. See [THREAT_MODEL.md](THREAT_MODEL.md).

Initial packaged attempts failed rather than being counted as passes: Chromium replaced the operation-specific caption, and small grid ordinals confused whole-document OCR. The title fix uses the BrowserWindow event and restores the bound title before showing the dialog; its regression emulates document-title replacement. The test driver now refuses ambiguous/sensitive-window screenshots and reads disposable phrase cells only in memory with an alphabet whitelist. An early caption failure captured an empty input dialog before any password was entered; that diagnostic was deleted. No generated phrase or entered password was saved in a screenshot. Two independent public fixture probes verified all12 displayed words without retaining pixels or words; complete random-root drills then passed. Test failures and their correction do not constitute independent security review.

# Implemented threat model and remaining trust

This is an implementation-author assessment, not independent security review. Protect recovery entropy/phrase, BIP39 passphrase/seed, derived keys, storage password/key and exact payment authorization. Address associations, journal and RPC credentials are privacy-sensitive too. A single recovery root shares compromise scope across every chain.

Only wallet-signer creates/imports/decrypts the root and derives signing keys. Passwords and imported phrases/passphrases use masked, bounded native GTK entries with password input hints; buffers and entry texts are cleared on completion/cancellation. The explicit product policy now permits a native Go-owned display of the phrase while recovery setup remains pending. It shows numbered, nonselectable words, then clears that label before requesting three recorded words in masked entries. A successful check persists recovery completion. Resuming interrupted setup requires app-password reauthentication; completed setup has no phrase-reveal/export operation. Neither Electron nor the network core receives phrase text, entropy, a secret QR or secret clipboard data. There is no encrypted portable-backup product operation, generic hash/calldata signing, arbitrary derivation, JS password input or plaintext recovery file. The numbered phrase avoids immutable Go strings; explicit Go/C staging buffers and widget text are cleared. GTK/Pango, cryptographic-library temporaries and display/input infrastructure can retain copies; best-effort wiping is not guaranteed erasure. No memory-locking guarantee is claimed. RLIMIT_CORE=0 and non-dumpable are checked at startup; failure refuses operation. Production binaries omit the `automation` build tag and test hooks.

The launcher verifies fixed child binary hashes, starts the public network coordinator over anonymous inherited pipes, then installs Linux no-new-privileges and TSYNC seccomp before execing Electron. The secret child separately installs the same filter. New AF_INET/AF_INET6/AF_PACKET sockets/socketpairs and io_uring setup/entry/registration are denied, including across existing Go threads and later Electron descendants. Unix-domain sockets remain available for GTK/display/session services. This is IP isolation, not a complete syscall/filesystem sandbox. The core has network access and RPC credentials while unlocked, but never receives the recovery root or storage password. Lock cancels its contexts and drops references to configured credential-bearing adapters. Already-running library/string copies can outlive those references.

Electron uses sandboxed renderer, context isolation, no Node integration, no webviews or devtools, restrictive local-only protocol/CSP, denied permissions/popups/navigation/downloads, and a narrow exact-field public bridge. Packaged fuses disable RunAsNode, NODE_OPTIONS and CLI inspection and require ASAR. Linux ASAR loading and local SHA manifests do not authenticate the publisher against an attacker who can replace all local files. There is no signed updater. A local menu or OS facility can still capture/inject input under the OS trust boundary. Component tests exercise the real production main/preload/renderer code using Electron doubles; they do not prove Chromium itself or every display server is safe.

Framed IPC is versioned, bounded, strict JSON, duplicate-key checked, correlated to request/method/session/generation and bound to inherited pipes. There is no localhost listener. Top-level null/scalar argument objects are denied. Only value-free rate-limited native activity frames can refresh inactivity during a pending prompt. A stale response or queued request cannot cross lock epochs, start a new secret child, restore old RPC settings or repopulate the ordinary UI. Main and renderer caches clear on lock/error and status polling never marks activity.

Lock's coordinator mutex serializes epoch change, context cancellation and child generation invalidation/kill. Secret process termination is the containment boundary for runtime copies. Five-minute inactivity uses real key/button events, not redraws or programmatic fills. OS screen-lock/suspend/shutdown events request lock, parent failure uses parent-death SIGKILL, and pipe EOF terminates the signer. UI coverage, actual private X11 input and subprocess races pass separately; real stock OS logout/suspend/Wayland matrix remains NOT_RUN. A compromised ordinary renderer can spam public activity, deny service, request native dialogs or misrepresent public data. It cannot replace the native credential/approval policy, but a compromised compositor, same-user malware or OS can spoof that surface.

Transfer plans bind network/profile, recipient, exact atomic amount, asset identity, fee/reserve, nonce/sequence, expiry, memo, all inputs/outputs and canonical payload. Each secure adapter independently decodes/reconstructs the allowlisted transfer and verifies its produced signature. Native approval and per-send password are mandatory. Plans/reservations persist before approval, signed bytes before broadcast. Unknown submission outcomes retain reservations and reconcile the original identity. Explicit cancellation releases only unsigned PREPARED state. There is no arbitrary message signing. Rollup/TON/NEAR fee estimates are labeled honestly where the protocol cannot enforce a signed total charge cap.

The live vault encrypts root, recovery descriptors, associations, RPC credentials and durable journal together with bounded Argon2id and authenticated XChaCha20-Poly1305. Copying a locked vault permits offline password guessing; choose a strong unique password. Headers permit only bounded reviewed KDF parameters. Atomic no-follow private file operations and single-writer flock defend accidental/malicious filesystem substitution within the stated owner checks. They do not defeat root, hostile filesystem/kernel, storage failure or rollback of an entire valid old directory. In particular, replacing a confirmed profile with older valid pending ciphertext can make native completion eligible again after password authentication; the pending-only reveal rule is scoped to the current authenticated generation, not an external monotonic record. Recording the phrase replaces portable encrypted-file backup verification. It restores canonical key derivation, while local journal, account/association/discovery metadata and credentials need independent reconstruction or reconciliation. The three-word check cannot prove that the complete offline copy will remain safe or legible. See [VAULT_FORMAT.md](VAULT_FORMAT.md) and [RECOVERY.md](RECOVERY.md).

RPCs can lie, correlate public addresses, censor, time out or omit history. Network/genesis/code/authority checks prevent known wrong-domain substitutions, but are not consensus proofs. TLS endpoints or explicit loopback nodes are required, redirects/response sizes/nesting/timeouts are bounded, and credentials remain encrypted at rest. Decred uses a verified-network authenticated trusted dcrd scan, not SPV. TON trusts TON Center-compatible data and verifies decoded transaction effects within bounded queries, not independent finality proofs. Every history view shows its finite scope; an incomplete scan is not a confirmed zero. No fiat oracle, analytics, remote scripts/fonts or custodial backend is included.

Tested defenses and residual gates are listed in [STATUS.md](STATUS.md), [COVERAGE.md](COVERAGE.md), [STRESS.md](STRESS.md) and the chain evidence files. Synthetic-canary absence applies only to the exercised paths and encodings. Full live-memory extraction, physical attacks, kernel/root control, signer/library supply-chain replacement, hostile X11/Wayland/input methods/accessibility/compositor and same-user capture/injection are outside the software wallet's protection claim. Independent review of the vault, GUI/IPC boundary, all adapters and build chain remains mandatory before production use.

Mainnet is the default process profile; an explicit `--profile=testnet` selects the separate developer vault. The launcher consumes this option and binds it to the coordinator/signer; renderer requests cannot switch profiles. Existing vaults are neither copied nor reclassified. Native receive/copy, preparation and signing require completed recovery setup on both profiles, enforced in Go rather than by disabled frontend controls. Signing rechecks eligibility before approval, after confirmation and after password reauthentication. A legacy verified-backup flag alone grants no authority. Account/RPC/password changes do not require recording the unchanged phrase again. A completed setup cannot be reset through public IPC to turn the completion action into a later reveal endpoint.

The mainnet provider defaults and read-only identity checks are documented in [MAINNET.md](MAINNET.md). Decred requires explicitly configured authenticated TLS access; an unconfigured or incomplete scan is unavailable, never a confirmed zero. Credential-bearing endpoint paths/queries are retained only in encrypted settings and Go networking; public network metadata exposes origins only. TON Center requests without an API key are paced locally, with context cancellation and no automatic request/broadcast retry. Public-provider quotas, hostile providers and independent production acceptance remain separate limitations.

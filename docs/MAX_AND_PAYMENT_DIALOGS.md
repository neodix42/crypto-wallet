# Max, fee estimates and payment dialogs

Max previously shared the final preparation route and saved a PREPARED operation. Repeated Max or a later preparation could collide with that account reservation and show a generic failure. Max and `quotePayment` now return read-only estimates; only explicit Send records an operation after fetching fresh state and fees. A quote is never signing authority. No reservation is released by quoting.

EVM Max now uses the smaller verified confirmed/pending balance, so a transaction already pending at the provider cannot inflate the amount available for another transfer. Failed or malformed pending observations remain errors.

A separate coordinator serialization defect converted typed transaction payloads into quoted JSON and reordered account/payload objects. This broke native TON validation and could change byte-sensitive plan digests. The public envelope now preserves exact object order and integer precision while redacting RPC endpoints; the native client unwraps the known payload field once. Adapter-authored TON, NEAR and EVM plans retain their exact payload, parameters, IDs and digests. Private signing messages are unchanged.

The Send form estimates fees after a valid recipient/positive amount stops changing. Edits, asset/tab changes, close, lock and explicit actions cancel stale read-only estimates without killing the signer or interrupting a payment. Failed estimates remain unavailable with a fixed actionable message. Send always recomputes; old estimates are labelled expired. Max sits beside the Amount input, fills whole-asset units and shows its fee budget. Native Max subtracts fees and protocol storage; token Max uses the full spendable token balance with separate native gas. Fee refunds, changing costs and required storage mean an exact zero balance cannot be promised.

History is an inert seven-column table. Send and Deploy open exact signer-authored approval/current-password dialogs. An existing valid matching unsigned preview can resume its original approval; expired or different unsigned plans require explicit cancellation in a dialog. Signed/submitted/unknown operations are reconciled by their original identity. Rebroadcast requires its own popup showing the original amount/address/transaction, reuses already-approved bytes, and never signs the current form or replaces the original. Cancelling a dialog leaves it unchanged. Already-signed/unsubmitted originals open consent directly and enter the existing reconcile-before-retry path, rather than attempting an invalid standalone ledger transition. Strict real-ledger transition tests cover the normal UNKNOWN/query-error path and fail-closed known-receipt cases; ledger rules are unchanged.

TON status and deployment details display one standard wallet ID, **0** or **42**. The former 2147483409 value is the encoded network/workchain representation of the original ID 0 profile; it is not a second wallet. Validation and signing retain that raw value internally. No wallet address, StateInit, profile or funded contract changes.

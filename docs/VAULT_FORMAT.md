# Vault and recovery format v1

The live vault uses the authenticated binary envelope below. This document describes `internal/vault`; it is not a cryptographic audit. No plaintext keystore or OS-keyring wrapping is used. Product recovery now imports a recorded BIP39 phrase, rather than creating/verifying/restoring portable encrypted backup files. Existing local ciphertext remains encrypted with the same algorithms and resource bounds.

All integers in the 72-byte header are unsigned big endian. The complete header is XChaCha20-Poly1305 associated data.

| Offset | Bytes | Meaning |
|---|---:|---|
| 0 | 8 | ASCII `LWVLT001` |
| 8 | 2 | Format version 1 |
| 10 | 1 | KDF identifier 1: Argon2id v1.3 |
| 11 | 1 | AEAD identifier 1: XChaCha20-Poly1305 |
| 12 | 4 | Argon2 memory, KiB |
| 16 | 4 | Argon2 passes |
| 20 | 1 | Argon2 lanes |
| 21 | 3 | Reserved, must be zero |
| 24 | 16 | Fresh OS-random salt |
| 40 | 24 | Fresh OS-random nonce |
| 64 | 8 | Ciphertext bytes including 16-byte tag |
| 72 | variable | Ciphertext and tag |

The derived storage key is 32 bytes. Default parameters are 262144 KiB, 3 passes, 4 lanes. Accepted memory is 65536–524288 KiB in multiples of 1024, passes 3–6, exactly four lanes. Format, lengths and these resource bounds are checked before any KDF. A process-wide mutex permits one active KDF. Plaintext is nonempty and at most 16 MiB. Truncation, appended data, unsupported versions/algorithms, nonzero reserved bytes and any authentication failure release no partial plaintext. Password creation accepts 12–4096 UTF-8 bytes with no normalization. Decryption permits legacy shorter inputs only to authenticate an existing envelope; no shorter password can be created by v1. Fresh salt/nonce are drawn with `crypto/rand` for every encryption, with no fallback.

The encrypted plaintext is strict JSON schema version 1: wallet ID, positive generation, `bip39-english-v1`, entropy (16/20/24/28/32 bytes), optional BIP39 passphrase, mainnet/testnet environment, creation birthday, `recoveryConfirmed`, account descriptors, transaction journal and encrypted RPC settings/credentials. `recoveryConfirmed` is true only after native recorded-word confirmation for generated/pending roots or acknowledgement of the recovery limits during known-phrase import. False or absent means setup is pending and cannot authorize receive, preparation or signing on either profile. A former schema-1 `backupVerified` member is accepted only for compatibility with existing local ciphertext; it is ignored as authority and does not imply `recoveryConfirmed`. Authenticated unlock clears this deprecated flag before persisting the current local vault. Older installed versions that reject the new member cannot be assumed to open newly written vaults. Duplicate keys at every depth, other unknown fields, trailing data and nesting above 32 are rejected. Account count and operation count are each bounded at 10000. Root/account/profile/journal metadata are authenticated together. Signed artifacts remain encrypted with the root. Public snapshots expose the completion boolean but omit all signed bytes, entropy, phrases, passphrases, passwords and RPC credentials.

Descriptors preserve family, immutable profile, actual index, network, public key, full address, contract/discovery/association parameters and hidden status. Hidden accounts remain recoverable and retain their index. Profile IDs and exact protocol details are in source and [chain evidence](STATUS.md). Decred stores xpub, receive/change counters, birthday, gap, per-branch address limit and block budget. NEAR named associations and Aptos rotated-address associations are checked against the derived key during recovery and current network authority before signing. TON retains its V5R1 parameters. Password rotation changes envelope encryption, never derivation.

Live profiles are `$XDG_CONFIG_HOME/localwallet/{testnet,mainnet}`, defaulting to `~/.config/localwallet/…`. `vault.lwv` is current, `vault.previous.lwv` preserves the previous ciphertext, and `writer.lock` is a single-writer flock. Directory creation and traversal use verified directory FDs and no-follow semantics. Private live-profile directories must be owned by the current UID with mode 0700; files are regular owner-only mode 0600 with one link. Symlinks, hardlinks, FIFOs and unexpected owners/modes are rejected. Atomic same-directory ciphertext writes use an unpredictable exclusive temporary file, full write, file fsync, rename and directory fsync. Temporary files contain ciphertext only. Tests inject failures at write/sync/rename/directory-sync and resource limits; either the complete old or complete new file may survive a crash. On live-vault persistence error the engine locks and returns no undurable signed artifact.

Creation persists an encrypted pending root before displaying its phrase, so cancelling or terminating during recording does not replace it with a new root. Correct recorded-word confirmation persists `recoveryConfirmed` through the ordinary authenticated atomic-write path. A persistence failure locks the engine rather than granting undurable authority. Resuming pending setup requires native app-password reauthentication; an already confirmed root has no completion/reveal action. Password rotation re-encrypts the same root and preserves completion. The app no longer offers portable encrypted-file export, verification or file restore. A recovery phrase plus its original optional BIP39 passphrase reproduces canonical keys into an empty profile under a newly chosen storage password; it does not reproduce every field of the old vault.

Generation detects inconsistent application state within a loaded session; it cannot detect an attacker restoring the entire directory or older valid ciphertext. There is no external monotonic counter or anti-rollback service. Replacing a confirmed vault with older authenticated pending ciphertext can restore recovery-completion eligibility after password authentication; pending-only phrase display is not a rollback-proof lifetime restriction. Phrase-only restoration does not contain additional account indices, hidden labels, associations, settings, DCR receive/change counters or transaction records. It reconstructs canonical index-zero accounts, with explicitly bounded account/address discovery for later activity. Reconcile prior payment identities before another payment: a fresh installation cannot recover a missing local journal from the phrase. Unknown outcomes in an intact journal preserve reservations and are never automatically re-signed.

Only schema 1 is supported. Unknown future versions fail closed. The optional completion member and ignored former backup member provide the stated in-schema compatibility; no successful cross-schema migration is claimed. Preserve and authenticate existing ciphertext and record the recovery phrase before relying on a new installation. `vault.previous.lwv` is a crash-recovery aid, not an independent backup. The phrase does not carry network selection or restore noncanonical associations; follow [RECOVERY.md](RECOVERY.md) and compare known public addresses.

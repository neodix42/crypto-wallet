## Current phrase recovery and desktop

The owner's recorded-phrase policy replaces encrypted portable backup creation, verification and file restoration. After explicit native password entry, Go generates one random BIP39 root, durably encrypts it, displays its phrase only in the native recording window, then checks three masked recorded words. Cancelling or answering incorrectly preserves the same pending root. Resumption requires native password reauthentication. Receive, public-address copying, preparation and signing remain denied by Go until confirmation on both profiles. Existing vaults keep their keys; the old backup flag grants no authority. Confirmed current generations have no repeated phrase-display/export operation. The app password protects storage and does not derive addresses; any original optional BIP39 passphrase remains separately required.

The final [fresh-installation drill](evidence/phrase-recovery.json) passed all six checks against three independent application copies, each with new processes, HOME/config directories and vaults. A randomly generated phrase restored all nine mainnet wallets at indices 0, 1 and 127: 27 exact public descriptors. Same-password and different-password restores matched, restarted locked, and unlocked identically. Only binaries/manifests were copied between installation trees; no wallet file or keyring state was reused. Public IPC, persisted files and process logs passed the tested plaintext/hex/base64 secret-canary checks. This simulates another machine on one host; separate physical-machine testing remains NOT_RUN.

The final [installed portable X11 drill](evidence/packaged-recovery.json) passed 20 checks: invalid password/phrase guidance, random phrase setup and incorrect-word denial, pending Send/Receive completion controls, cancellation, native reauthentication and QR continuation, generated-phrase recovery in an empty profile, independent fixture addresses, table copy/balances, Settings journal, displayed-QR decoding and native copy, Send form, tab closing, restart/unlock, isolated testnet and additional account tabs. Logs contained neither Mesa loader errors nor ordinary IPC handler stacks. Only public/disposable fixture addresses reached read-only providers; Send testing stops at the form. Owned private Xvfb, no debug port or sandbox bypass, and memory-only synthetic phrase OCR were used. Real hardware, full Wayland workflows and the supported installed OS matrix remain NOT_RUN.

The [phrase checklist](PHRASE_RECOVERY.md), [recovery instructions](RECOVERY.md), [desktop/signer tests](FRONTEND_SIGNER_TESTS.md), [layout](WALLET_LAYOUT.md) and [actions](WALLET_ACTIONS.md) describe behavior and limits. Phrase restoration reproduces canonical keys/accounts, not unknown named/rotated associations, Decred discovery counters/settings, RPC credentials or the local payment journal. Reconcile original uncertain transaction identities before creating replacement payments.

## Distribution and remaining gates

`make build` creates Go components without Node/Electron or Debian packaging. `make package-go` verifies their runtime versions and archives them; these backend assets have no standalone main wallet interface. The optional complete desktop uses `make install`, providing `./wallet` plus its managed runtime without altering profiles. Neither built distribution reads `.tools`, which remains an untracked developer/test cache. VERSION or the validated WALLET_VERSION override supplies the executable, desktop, archive and workflow tag/release version. The versioned development prerelease workflow was implemented and linted; remote execution/publication remains NOT_RUN. See [BUILD.md](BUILD.md).

All nine mainnet networks and eleven assets remain supported. Earlier read-only provider checks passed 29 assertions across eight domains. Authenticated synchronized Decred mainnet access is BLOCKED until an operator configures trusted TLS dcrd; the wallet remains visible with unknown balance. Earlier container startup probes remain BLOCKED by Chromium sandbox configuration. No sandbox bypass was applied. Limited preceding X11/virtual-Wayland startup evidence is not full OS acceptance.

Resource limitations remain: bounded Decred scanning with a 10000-row internal ceiling, TON history searches of 100 transactions, 1MiB IPC frames, no general paginated desktop retrieval and a 100000-request replay cap per continuously active IPC session. Incomplete/oversized data is an error, never verified zero. A phrase cannot resolve installation journal uncertainty, whole-directory rollback, OS/display compromise or already copied secrets. Native clearing is best effort, not proof of erasure from every library/display buffer.

Production release remains incomplete: public funded testnet roundtrips and applicable third-party wallet/version interoperability; clean Ubuntu 24.04/26.04 X11/Wayland, lock/suspend/install/upgrade/recovery acceptance; complete process/crash/canary campaign; 24-hour workload; independent threat/vault/adapter/build review; licensing and publisher authentication. `make verify-release` fails until mandatory evidence passes. The current [traceability table](traceability.json) distinguishes passing local invariants from those broader NOT_RUN/BLOCKED gates. A development prerelease does not close them. No publisher authentication/update mechanism or independent audit is claimed.

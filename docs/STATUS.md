# Implementation and release evidence

This is an unsigned development testnet candidate, not an audited production wallet. Every root specification and applicable repository instruction was read before implementation. The initial repository had specifications and no wallet code; no applicable AGENTS.md existed. The owner subsequently committed the implementation/specification snapshot at 88ae7006c4492eb3415d40821d664dcb5890d9c2; further working-tree changes are identified by the delivered source manifest, rather than claiming that base commit alone is the candidate.

PASS means the named scope was actually exercised. NOT_RUN means a required execution has not occurred. BLOCKED identifies a demonstrated environmental obstacle. A local node, SDK fixture, short soak or component test never substitutes for a missing external gate. Test data are public synthetic inputs; no real user secret was used and no mainnet funds were automatically sent.

The package's displayed version, Electron metadata, Go public runtime identity, Debian version and release name/tag share VERSION or the validated WALLET_VERSION override. `make build` now reports prerequisites and bootstraps pinned runtimes instead of silently rejecting another shell's tool versions. `make install` places the complete runtime at the repository root behind ./wallet. It does not write a system package or alter profiles.

Actual chain scope and primary provenance: [EVM/Core](EVM_CORE.md), [NEAR/Aptos](NEAR_APTOS.md), [Decred/TON](DCR_TON.md). All required domains have real derivation, protocol construction and signing; they are not all publicly accepted or independently reviewed. Core has no official local validator here. ZEN runtime tests run the actual frozen canonical contract code on private chains, not a pretend token return value. Network observations and independently generated fixtures are retained under tests/oracles. Those observations alone are not transfer receipts.

Measured coverage is enforced per package, with all shipped Go code and every shipped JS file included. Cross-package Go instrumentation counts production dependencies exercised by real command/integration tests. Native GTK coverage is unioned from a separately instrumented test build; automation-only helpers are explicitly non-shipped, never bundled in the candidate. Go measures statements, not branches; C/GTK/Electron internals are third-party code outside these percentages. [Coverage review](COVERAGE.md), [desktop/signer tests](FRONTEND_SIGNER_TESTS.md), [native activity](NATIVE_ACTIVITY.md) and [stress measurements](STRESS.md) explain their limits. The final source-stable rerun passed all22 shipped Go package floors; the frontend has30 passing component tests and100% measured statements/branches in all5 shipped JS files. Compact reports are retained in docs/evidence; full logs/coverage HTML remain in reports. Remaining unexecuted blocks are indexed and reviewed without removing their guards.

The uninstrumented packaged X11 recovery drill passed native input-only import, verified address/QR and copy, encrypted portable backup creation/reopen, restart requiring unlock, fresh-profile restoration and tested persisted/log canary scans. It runs on an owned Xvfb display, with no debug port, secrets in args/env/clipboard, or sandbox bypass. It uses a fresh profile on this host; it does not certify a clean separate Ubuntu installation or Wayland. Disposable Ubuntu containers install the real package and probe native startup; Chromium container restrictions can block startup. That is reported BLOCKED without weakening sandbox policy.

Bounded stress exercises100000 malformed IPC frames,10000 mixed address/amount/URI inputs across test profiles,1000 concurrent reservation scenarios with real signed fake-ledger transactions, outages/rate limits/lost responses, and production-KDF lock/reopen/backup/discovery/history cycles. Resource budgets precede measurement. Ordinary runtime and TSAN instrumentation have separate disclosed RSS profiles, including retained failed instrumentation-versus-production-budget evidence. The short soak smoke passed its actual duration; the required 24-hour campaign did not run. A real X11 native-input campaign passed5m12s, and an uninstrumented preceding runtime kept a native prompt live through5m22s of input then killed it after301s without input. Exact binary scope is retained in the reports; the full OS/release gate remains NOT_RUN. A dedicated self-hosted nightly workflow is provided; absent runner execution is NOT_RUN.

Release cannot be called complete while any mandatory gate is missing. `make verify-release` fails on those rows. Public funded testnets, real installed OS/display sessions,24-hour execution and an external audit require evidence beyond this development session. A development prerelease workflow is not authorization to declare those gates passed. There is no publisher authentication/update mechanism and license-obligation review remains incomplete. Read the [threat model](THREAT_MODEL.md), [recovery](RECOVERY.md), [format](VAULT_FORMAT.md) and [build](BUILD.md) documents before any use.

Resource limits remain user-visible development constraints: Decred has bounded scans and a10000-row internal record ceiling, TON history searches100 transactions, and IPC frames are limited to1MiB. Very large account/journal/discovery reports can exceed that boundary; general paginated desktop retrieval is not implemented. Those limits must be addressed/tested for large wallets before a production claim; no oversized result is silently labeled an empty balance. A continuously active public IPC session also has a100000-request replay-map cap and must restart after exhaustion. The24-hour component soak does not certify an indefinitely active Electron session.

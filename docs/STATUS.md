The owner subsequently committed the implementation/specification snapshot at 88ae7006c4492eb3415d40821d664dcb5890d9c2; further working-tree changes are identified by the delivered source manifest, rather than claiming that base commit alone is the candidate.

PASS means the named scope was actually exercised. NOT_RUN means a required execution has not occurred. BLOCKED identifies a demonstrated environmental obstacle. A local node, SDK fixture, short soak or component test never substitutes for a missing external gate. Test data are public synthetic inputs; no real user secret was used and no mainnet funds were automatically sent.

## Current onboarding and distribution changes

Default make/build now compiles Go components only, with no Node/Electron or Debian packaging. make package-go verifies and archives those backend components. The optional complete desktop is built with make package-desktop / make install and retains its bundled Electron runtime; it also has no Debian packaging. Production runtime code never reads .tools. That directory remains untracked developer/test cache.

First-run setup is gated on metadata-only safe storage checks, then explicit native password entry, OS-random shared BIP39 root generation and all configured initial network accounts at index0 under Main account. The generated phrase is never shown. Existing/unavailable/orphaned vault state cannot route into new-wallet creation, including through direct Go IPC. A verified backup remains the recovery mechanism. These changes do not satisfy outstanding independent/public-network/OS/24-hour release gates.

The [first-run security evidence](evidence/onboarding-security.json) records the exact affected-suite command: `go test -race -p 2 ./internal/vault ./internal/signer ./cmd/wallet-core ./cmd/wallet-signer -count=1 -coverprofile=reports/presence-coverage.out -covermode=atomic`. All four packages passed on 2026-10-23: vault 95.6%, signer 96.5%, core 95.8% and signer command 98.7% statement coverage. The tests cover unsafe storage, a surviving authenticated previous generation, locked JSON without secret fields, and nine deterministic Create/import/Restore collisions introduced during native input. An additional real filesystem collision after staging fsync verifies that atomic no-replace publication preserves a late primary file. Initialization rechecks storage at commit, never copies/replaces a previous generation, and locks/wipes on failure. This is internal source/runtime review; it is not an external audit or proof of atomic exclusion across both filenames against arbitrary uncoordinated same-user filesystem changes. A post-commit previous-file conflict stops the current session and preserves both files; no durable conflict quarantine across restart is claimed.

The current mainnet change retains all nine mainnet networks and eleven assets. Read-only provider checks passed 29 identities/metadata/method assertions across eight public domains. Live authenticated Decred access is **BLOCKED** until an operator configures its TLS dcrd endpoint; the Decred wallet remains visible and unknown, never replaced by a public-explorer approximation. Mainnet selection does not complete the release gates. Internal review additionally found and fixed stale mainnet backup authorization for already-prepared payments and cross-wallet Decred discovery controls; targeted regressions, the full race suite and the eleven-mutant gate pass. This implementation-team review is not independent security approval.

The current layout/receive change has its own source- and artifact-bound [evidence](evidence/wallet-layout.json). All 53 frontend tests and thirteen short native tests pass; the optional five-minute native case is skipped in this short run. A separate owned 1024×768 Xvfb/GTK allocation test keeps Copy address and Done visible with one hundred guidance lines. The full Go race suite, vet, Go-only archive verification, portable build/fuse verification and limited X11/virtual-Wayland startup probes pass. The first packaged layout attempt failed in the test driver while accepting a native file selection; its report is retained, then a fresh run passed all 22 checks after waiting for GTK path resolution. These results do not recertify historical funded-network, independent-review or long-duration campaigns.

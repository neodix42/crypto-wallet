# Recovery and ordinary use

Generated phrases are never displayed or exported. Recovery of a generated wallet requires an authenticated encrypted portable backup and the password used for that particular backup. Losing either can permanently lose access. There is no reset service or hidden master password. Storage passwords do not determine addresses; a BIP39 passphrase does.

Start the application as an ordinary user. Create defaults to English BIP39 with 12 words; a separate 24-word option exists. Passwords and already-known import phrases/passphrases are entered only in the masked native Go window. No reveal toggle, Electron password field, recovery clipboard or secret QR exists. Import accepts valid English BIP39 lengths 12,15,18,21,24 with exact single ASCII word spaces and NFKD rules. It does not silently repair a phrase. An optional imported BIP39 passphrase is exact and changes all derived accounts. A typo can produce a valid different wallet; verify known public addresses. An unknown balance never proves zero funds.

Before mainnet receive or send, a verified portable backup is mandatory. The supplied desktop candidate is testnet-only while release gates remain incomplete. In the wallet, choose **Create & verify encrypted backup**. Select an existing writable folder owned by your user, such as your ordinary Documents folder with mode 0755 or a private folder with mode 0700. Other users must not have write access to it; shared writable folders and symbolic-link paths are rejected. Choose a new filename; overwriting is rejected. The encrypted backup is owner-only (0600). The wallet does not change the folder's permissions or create a lockfile there. The Go signer encrypts, writes, reopens, authenticates, validates derivation and compares recovery descriptors, associations, discovery state and journal with the active vault before marking it verified. A copied file without this reopen step is not a verified backup. Keep an independent copy on media you control. An encrypted file is still sensitive; the app never uploads it.

For offline restoration, install the wallet on the supported system, disconnect networking if desired, start an empty testnet/mainnet profile matching the backup, choose **Restore into empty profile**, select the encrypted file through the native chooser, and enter its backup password. The source must be a regular owner-only file in an existing folder owned by your current user that other users cannot modify. A safe read-only source folder is accepted; restore creates no files there and changes no permissions. Recovery needs no original username, keyring or installation. The destination profile remains owner-only (0700), with private vault files (0600); an existing vault is never overwritten. Preserve an existing profile separately and use a fresh OS user or private `XDG_CONFIG_HOME` if you need a separate destination. This environment variable selects only a data directory, not secret input.

Restoration validates the complete root, profiles and account descriptors locally before writing the destination. It restores all recorded indices, hidden accounts, NEAR named associations, Aptos original/rotated-address associations, TON contract settings, Decred discovery counters and unresolved payments. It starts locked after every application restart. Unlock requires the native password prompt. Query balances and history only after selecting the correct network. Reconcile every unresolved payment before another send; a timeout can mean the original was accepted. Retry resubmits the persisted bytes, never automatically signs a replacement.

An older backup cannot include later activity. **Recover account indices** explicitly reconstructs up to 20 canonical account groups per request, with inclusive indices 0–999999. Repeat deliberate bounded ranges when necessary. This is local key discovery, not a declaration that all balances/history were searched. Hidden accounts can be shown and restored without renumbering. Update and verify the backup after account/discovery changes.

For Decred, explicitly select an appropriate birthday block, address gap (1–100), per-branch address limit (up to 10000), and block scan budget (up to 2000000;0 selects default10000). Scans use authenticated trusted dcrd access, not SPV. An incomplete scan is an error, never zero funds. Older receive/change gaps require increasing bounds or starting earlier. A verified checkpoint is meaningful only within the displayed range. Keep current backups after issuing addresses. Bounded history on other chains is also not exhaustive archival discovery.

Phrase-only import reproduces this application's canonical accounts. It does not find arbitrary NEAR names, rotated Aptos original addresses, historical TON contracts, third-party paths or Decred gaps. Named/rotated associations require the dedicated Go-verified association operation. TON is BIP39/SLIP-0010 Wallet V5R1, not a native TON mnemonic. Unsupported contracts/schemes fail closed. HyperCore spot and HyperEVM use separate balances/receipts; initial Core recipient activation remains a documented limitation. A shared EVM-format address does not establish Core activation or move funds between ledgers.

Each send has an immutable exact plan, a Go native summary and per-send password reauthentication. Inspect the full recipient, actual network, token contract identity, amount, fee currency, reserve/cap, all Decred outputs and memo. Base/Horizen rollup charges, NEAR fees and TON fees include estimates/reserves where the protocol has no signed total cap; inspect those labels. Decred payments currently use a nonzero wire expiry: recipient and change outputs require the network’s CoinbaseMaturity before spending (256 confirmations on mainnet;16 on testnet3/simnet). This delay is shown in native approval and immature-output history. Locking kills the secret-bearing session and cancels ongoing requests; an already signed/broadcast payment can still execute. Automatic lock defaults to five minutes of real input inactivity, and OS session lock/suspend also requests it. A compromised OS can defeat local input/display protections.

Password rotation preserves addresses. The current live vault rejects the old password after a successful change, but old copies remain decryptable with their old passwords. Rotation cannot revoke a copied backup. Create and verify a replacement backup after rotation, and manage old copies deliberately. No secret-reveal recovery utility is bundled.

Evidence: all-family encrypted roundtrip, account-range/hidden metadata, password change, corruption, cancellation and crash tests are in `internal/signer`/`internal/vault`. Ordinary-folder export, read-only restore, collision/link/permission checks and rejected-input feedback are covered by `internal/vault/backup_test.go` and `internal/signer/feedback_test.go`; targeted race and coverage results are in `reports/password-backup-regression.json`. Native packaged recovery has its own report. Fresh-profile recovery on this host is distinct from the required clean Ubuntu 24.04/26.04 X11/Wayland matrix, which remains a release gate.

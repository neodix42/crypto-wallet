# Recovery and ordinary use

The optional Bybit integration does not change deterministic wallet keys. The phrase cannot restore Bybit API credentials, regional beneficiary information, exchange account access or the local exchange-operation journal. Reconnect only after checking the original account/operations independently; restoring a phrase must never automatically repeat an uncertain deposit, order or withdrawal. See [EXCHANGE.md](EXCHANGE.md).

The recovery phrase is the backup of the wallet's cryptographic root. The app no longer creates, verifies or restores encrypted portable backup files. The live vault remains encrypted. There is no password reset service or hidden master password.

All current application windows use Wails/React with system WebKitGTK under the 2026-10-28 owner instruction. Earlier Electron/native-GTK interface requirements are superseded; Go still generates entropy, validates restoration, checks recorded words/passwords and signs approved transactions.

On first launch, choose **Create wallet · 12 words** (or the explicit 24-word option) and enter a new app password twice in the dedicated masked private wallet dialog. It accepts 12–4096 UTF-8 bytes without normalization. Go generates a cryptographically random English BIP39 root: 12 words by default, with a separate advanced 24-word option. A password, a user-written sentence and the frontend random source never supply the entropy.

The dedicated private wallet **Record recovery phrase** dialog then shows the numbered phrase supplied by Go. Write every word in order and store the copy somewhere private and offline. Anyone who obtains it can derive the wallets. The phrase cannot be selected or copied, and there is no secret QR, print or save-file action. It crosses only the dedicated transient prompt channel; the ordinary portfolio and its public API never receive it. After **I wrote it down**, the phrase disappears and three masked entries ask for words 2, 6 and the final word. Go verifies those words; correct entries record completion in the authenticated live vault and enable receive and payment authorization on both profiles. This checks the requested words; it cannot prove the completeness, durability or secrecy of the user's offline copy.

Cancelling either step or entering incorrect words leaves the same encrypted root pending setup. It does not generate a replacement root. Use **Finish recovery phrase setup**, authenticate with the app password and finish recording that phrase. Once setup is confirmed, this setup-completion action cannot reveal it again. To record another offline copy, use **Settings → Wallet → Back up recovery phrase**, confirm and enter the current app password. The separate private wallet dialog shows numbered words; choose **Done** to close it. Every view requires confirmation and password verification in Go. Wrong password, cancellation, lock, pending setup or failed storage state prevents display. This is read-only: the encrypted vault, its generation, completion, addresses and journal do not change. The owner-authorized **Copy phrase** button copies the ordered words without numbering through the Go-owned clipboard control, only for this authenticated backup view. Other apps and clipboard history may retain them; clear the clipboard after use. No automatic clearing or OS-wide erasure is promised. Setup remains noncopyable, and there is no file, print or secret QR action. An original optional BIP39 passphrase is not displayed and must be kept separately. Replacing the entire profile with older valid pending ciphertext can restore pending status; the wallet has no external anti-rollback authority. Existing vaults from the former backup workflow also require this completion step; their old verified-backup flag does not grant payment authority. Public balances and account listings do not prove recovery setup is complete.

To restore on another installation, start an empty profile on the correct network and choose **Restore from recovery phrase**. Enter the desired app password twice, the complete phrase and any original optional BIP39 passphrase in the dedicated masked private wallet dialog. Confirm the recovery-limits notice and compare known public addresses before use. Recovery does not require the old machine, username, OS keyring, application files or storage password. Using the same app password is supported, but a different new app password reproduces the same blockchain wallets too. The app password only encrypts that installation. An optional BIP39 passphrase is a different secret: it changes the derived wallets and must be supplied exactly. New generated wallets use an empty BIP39 passphrase. A passphrase typo can create different valid wallets; an empty or unavailable balance cannot prove which passphrase was intended.

Import accepts valid English BIP39 lengths 12, 15, 18, 21 and 24, with the documented checksum, exact single ASCII word spaces and NFKD rules. It does not translate words or silently repair a phrase. TON uses this application's BIP39/SLIP-0010 Wallet V5R1 profile, rather than a native TON mnemonic. External-wallet acceptance of each phrase length is a separate interoperability claim.

The default profile is mainnet. `./cryptowallet --profile=testnet` opens separate developer data; selecting a profile never migrates or reclassifies a vault. Mainnet is a connection default, not a claim that independent review or production acceptance is complete. Restore into an empty private profile: existing `vault.lwv` or `vault.previous.lwv` prevents creation of a replacement root. An unavailable profile is not treated as empty. Preserve an existing profile separately and use a fresh OS user or private `XDG_CONFIG_HOME` for an isolated destination. That environment variable selects only a data directory, never secret input.

Phrase restoration initially reconstructs this application's canonical index-zero accounts for every supported network in the selected profile. **Recover additional account indices** in Settings derives an explicit inclusive range, at most 20 account groups per request, within indices 0–999999. Repeat deliberate ranges for accounts added later. This is local key derivation, not a statement that all balances or transaction history were searched. Hidden status, labels, RPC credentials/settings, pending-payment journal, named/rotated associations and issued-address discovery counters are installation metadata; the phrase does not encode them. Never assume another installation knows whether a payment was already signed or submitted. Reconcile its original public transaction identity before initiating another payment.

NEAR names, rotated Aptos original-address associations, historical TON contracts and arbitrary third-party paths require separate verified metadata/discovery. The dedicated association operation verifies supported NEAR/Aptos associations in Go. Unsupported schemes or contracts fail closed. HyperCore spot and HyperEVM remain separate balance and receipt domains. A common EVM-format address neither proves Core activation nor transfers funds between ledgers.

For Decred, retain the relevant account indices and discovery bounds separately. Set an appropriate birthday block, address gap (1–100), per-branch address limit (up to 10000), and block scan budget (up to 2000000; 0 selects the default 10000). Discovery uses authenticated trusted dcrd, not SPV. Restore cannot infer old receive/change counters from the words alone. Scan an adequately early range and increase bounds for historical gaps. An incomplete scan is an error, never zero funds. A verified checkpoint establishes only the displayed range; finite history queries on other chains are not exhaustive archival discovery either.

The wallet starts locked after every restart. Unlock uses the dedicated private wallet app-password prompt, verified in Go. Each send still requires an immutable exact plan, a dedicated private wallet confirmation of Go-authored details and password reauthentication. Inspect the full recipient, actual network, token identity, amount, fee currency/reserve/cap, every Decred output and memo. Base, NEAR and TON display estimates/reserves honestly where their protocols cannot enforce a signed total charge cap. Decred's nonzero wire expiry causes ordinary recipient/change outputs to require CoinbaseMaturity before spending: 256 confirmations on mainnet and 16 on testnet3/simnet. Lock cancels ongoing requests and kills the secret-bearing process; it cannot recall a signed or broadcast payment. Unknown outcomes retain the original transaction identity and never automatically create a replacement payment.

Password rotation preserves the phrase, all addresses and recorded recovery completion. A copied older live vault remains decryptable with its old password; changing a local password cannot revoke an already copied secret or vault. The Wails private phrase dialog deliberately exposes the phrase to its trusted React/WebKit view and bounded transient Go prompt transport. Those components, the OS and display/input environment are trusted with prompted credentials and phrase text. A compromised prompt/web engine, OS, compositor, same-user capture tool or malicious accessibility/input service can steal inputs or spoof display. Go generation does not prevent this. Best-effort DOM/buffer clearing cannot guarantee erasure of immutable JavaScript/Go strings, WebKit/IPC or OS copies. The current Go roles and WebKit renderer are unconfined as explicitly requested; application restrictions are not a kernel isolation boundary.

Current evidence is tracked in [PHRASE_RECOVERY.md](PHRASE_RECOVERY.md) and [STATUS.md](STATUS.md). Isolated-prompt component tests check masked input, exact value preservation, phrase acknowledgement, separate challenge presentation, cancellation/hide/late-delivery clearing, inert transaction details and Go-bound public Receive copy. `make test-recovery` uses the production prompt protocol and independent installation directories; `make test-wails-wallet` tests actual current Wails interaction. `make test-packaged-desktop` retains historical Electron regression coverage. A protocol simulation or component double alone does not prove the packaged display boundary. Previous native GTK/Electron reports apply only to those former interfaces and do not certify current Wails behavior. Separate physical-machine, clean supported-OS/Wayland, public funded-network and independent-review gates require their own recorded evidence.

Horizen mainnet/testnet are retired from active wallet derivation and RPC/signing selectors. Opening an older vault still authenticates and retains their historical encrypted descriptors, endpoints and journal. It does not delete or migrate funds. Canonical Base ZEN remains active; standard Ethereum/Base token watch policies must be approved again after phrase-only restoration. Base discovery is read-only and may rediscover candidates, but never restores a previous signing approval automatically.

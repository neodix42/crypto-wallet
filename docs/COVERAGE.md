# Go coverage and remaining-path review

This is an internal implementation review, not an external audit. Go measures statements, not branches. A passing percentage does not establish network compatibility, a clean-desktop recovery drill or production readiness. Public funded testnets, the full installed OS/display matrix, the 24-hour campaign and independent review retain their separate recorded statuses.

## Reproduction and evidence integrity

Run `python3 scripts/go-coverage.py` or `make coverage`. The wrapper executes the real application/unit/stress tests with atomic cross-package instrumentation, enables the pinned local dcrd simnet and TON contract emulator when available, and runs the real private-X11 GTK input suite. It unions identical production blocks from both profiles, retaining one statement denominator and the maximum observed execution count. This counts real calls across package boundaries rather than treating their own isolated test binaries as the only coverage source.

The wrapper records each source/test/module SHA-256 at the start and refuses changed-source measurements. It checks the pinned dcrd source-module identity before launching its isolated simnet. Missing local prerequisites remain **BLOCKED**; explicit Go skips remain **NOT_RUN** or **BLOCKED**, with reasons. Tests use public synthetic fixtures and disposable OS-random roots. No mainnet payment or real user secret is used.

Only the exact `internal/secureui/automation.go` and `internal/secureui/recovery_automation.go` paths (both `automation`-tagged GTK fixture injectors absent from production) and independent non-shipped oracle programs are excluded. Their exact paths/reasons are recorded. The coverage-integrity regression also supplies an unknown `other_automation.go` source and requires it to remain included, so this is not a filename-pattern exclusion. Production native input, clipboard pumping, lifecycle, all signing adapters and all application binaries remain included. Third-party libraries and native C/GTK code are not instrumented by Go's statement counters. They retain independent fixtures, runtime tests and audit obligations.

`reports/coverage.json` is the per-package floor result; `reports/go-coverage.json` records suites, source/profile hashes, local gate outcomes and skipped tests. `reports/go-uncovered.json` contains every unexecuted production block with its exact source excerpt and statement count. `reports/go-functions.txt` and `reports/go.html` provide function and source views. The block index below ties that machine report to the review disposition.

`python3 scripts/coverage-test.py` verifies that profile union does not multiply denominators or invent hits, exclusions remain explicit and limited to non-shipped sources, changed block shapes/modes and negative counters are refused, empty coverage is not passed, and critical security packages enforce 95%. The launcher uses the 90% application-glue floor; core, signer CLI, secure UI and supervisor use the stricter 95% security floor.

## Security and funds paths exercised

The recorded suites cover immutable plans/native approval, changed recipients/fees/networks, signature verification, durable signed artifacts before broadcast, old-identity reconciliation, reservation retention, failed persistence locking, unsigned cancellation, session/generation races and encrypted recovery. A specific coordinator regression changes the epoch after the durable `SUBMITTING` update and proves the adapter never broadcasts while the signed identity remains recoverable.

The current phrase-recovery regressions create real OS-random BIP39 roots across all six required families and restore their exact canonical descriptors in independent empty profiles. They cover 12-word mainnet and 24-word testnet roots, indices 0, 1 and 127, the same or a different app storage password, restart/unlock, and a separate nonempty BIP39-passphrase case. Mainnet still contains nine networks and eleven assets; explicit testnet/local coverage is retained. A restored phrase does not reproduce a lost local journal, undiscovered associations or historical address counters. The former `Engine.Backup`/`Restore` methods now exist only in `_test.go` helpers for retained filesystem hardening regressions, with no product dispatch or UI action. Environment mismatch checks still reject opening a vault under the wrong profile. The production launcher bootstrap verifies mainnet by default, explicit `--profile=testnet`, and rejection of malformed or conflicting profile arguments. Locked snapshots identify their selected environment without exposing accounts or credentials. The public network registry keeps mainnet and test/local networks separate; authenticated Decred settings remain explicitly unconfigured until supplied by the user.

Receive/copy, preparation and signing require recorded recovery completion on both profiles. The pending-root tests preserve the same encrypted root across cancellation, restart and password reauthentication, reject repeated disclosure after confirmation, ignore a former verified-backup flag, and fail closed on missing native recovery support or failed acknowledgement persistence. Callback faults lock the engine during import confirmation, phrase display, password input and the separate BIP39-passphrase reminder; none can acknowledge a locked or replaced root. A signing regression explicitly revokes the completion flag in test state before Sign, during native approval and during password reauthentication. It requires no signature and preserves the original journal or cancels the unsigned operation as appropriate; confirmation-time revocation also prevents opening the password prompt. Restoring authority in that test uses a test-only helper, while separate recovery tests exercise the actual production completion path. No public operation resets completion or reveals a completed root. These tests use local encrypted files and offline plans, with no mainnet broadcast. RPC metadata tests remove credential-bearing paths, queries and userinfo before public IPC, and native configuration tests reject foreign-profile networks, missing Decred authentication and plaintext mainnet dcrd transport.

TON pacing tests use a synthetic HTTP transport to enforce spacing for unkeyed official TON Center requests, cancel a queued or delayed request at its context deadline, and preserve the configured API-key/header and custom-node paths. This is a local request limit, not a guarantee against quotas consumed by other applications sharing a provider/IP. It never retries a broadcast. Public mainnet endpoint identity probes have separate evidence in [MAINNET.md](MAINNET.md); this coverage measurement does not establish funded-mainnet execution.

First-run tests require primary and previous generations to be absent before creation or phrase import. Existing, corrupt, unsafe and orphaned entries remain existing/unavailable rather than a new-wallet invitation. Six product-path cases introduce primary, previous or both ciphertext files during Create/phrase-import native input, then verify rejection, secret cleanup and unchanged original bytes. Three additional cases retain equivalent checks through a test-only legacy file-restore helper; they are not product restore acceptance. A separate real filesystem test introduces a primary after staging fsync; the kernel's `RENAME_NOREPLACE` preserves that late file. Initialization never copies a previous generation. These are bounded collision tests, not proof of atomic exclusion across two names against an arbitrary same-user filesystem writer.

Real native tests cover masked inputs, UTF-8 byte limits, cancellation, fixed value-free failure notices, PNG display, file selection, public clipboard ownership, scrolling exact effects and unavailable display. Recovery-specific tests use published 12/24-word BIP39 vectors and check explicit recording, masked word challenges, wrong/overlong words, cancellation at each stage, unchanged public clipboard and empty phrase-label/entry text at widget destruction. They never save or OCR a generated phrase. The combined production-only profile measures `internal/secureui` at 99.07%; its unexecuted Go guards are the partial-result cleanup loop and failed recovery staging allocation. This union includes the private-X11 native profile (14 passing tests, one explicitly skipped long-duration test, 98.3% on its narrower automation-inclusive run) without duplicating statement denominators. Background timers, programmatic field assignments, redraw/focus and clipboard events produce no activity. Private/public activity frames carry only `{}` with current request ID/session. Tests reject stale/malformed/flooding events and prove that initial locked prompts expire while their network access remains denied.

The response-driven GTK receive regression exercises [the native receive window](../internal/secureui/native.go) with an exact address supplied independently of the summary. It verifies that **Done** leaves the clipboard unchanged, **Copy address** copies the separately supplied address, and copying followed by Cancel rejects completion while retaining the public address deliberately copied by the user. Empty/NUL-bearing addresses, missing or invalid PNGs and direct cancellation are rejected. [Signer tests](../internal/signer/receive_copy_test.go:26) independently decode each supported test/local network QR, compare the copied-address argument with the current public descriptor, retain the recorded-recovery gate, require accepted verification for the older explicit-copy endpoint, and check exactly one durable Decred receive-index advance after cancellation. These tests make no claim of clipboard rollback or OS-wide erasure.

[The bounded-layout native regression](../internal/secureui/boundaries_automation_test.go:110) supplies 100 lines of public guidance and checks that the mapped Copy address and Done controls remain inside the window. The current native suite reruns it on its private 1280×1024 display. An earlier owned 1024×768 Xvfb run recorded a 650×680 window in `reports/receive-small-display.json` and `.log`; its source hashes bind that historical run. The body scrolls independently of the action buttons; only the displayed QR is scaled to 320 pixels, while the original 512-pixel PNG remains unchanged. GTK response injection and allocation checks establish this local behavior; they are separate from the real XTest input/activity tests and do not establish a clean installed desktop or Wayland acceptance result.

The separate source-bound recovery geometry run, `reports/phrase-native-focused.json` and `.log`, uses an owned 1024×768 Xvfb display. Both 12/24-word dialogs remain 650×600, with the phrase inside a scrolling body, and the masked challenge remains 650×480; Cancel/confirmation buttons are mapped inside the window. Its test-only GTK responses and destruction inspections are not a physical-machine or compositor acceptance test. The shipped Go app restoration driver and installed Electron workflow have separate artifact-bound evidence in [PHRASE_RECOVERY.md](PHRASE_RECOVERY.md). They use private XTest input, keep disposable generated-phrase OCR in memory-only pipes and reject saving native-secret-window screenshots. The Go driver additionally scans public IPC against canaries, including frames received before the phrase became known. They do not convert the unrun supported-OS or independent-review gates into passing results.

The [process-lifetime review](PROCESS_LIFETIME.md) covers the Linux creator-thread parent-death hazard. The launcher keeps one OS thread through child startup and `Exec`; the supervisor retains a dedicated locked creator thread until each signer is killed and reaped. Actual kernel controls reproduce child `SIGKILL` when an unowned caller thread retires. The fixed Child survives caller-thread retirement, answers a subsequent RPC, releases every owner over eight restarts, and receives `SIGKILL` after abrupt parent-process death. The last test independently reaps the child through a private subreaper and makes the peer wait on EOF, so ordinary pipe closure cannot pass it. These regressions confirm the isolated mechanism; they do not attribute an earlier packaged failure without its missing thread trace.

The successful isolation helper tests actual TCP/UDP sockets on all Go threads, raw packet/socket families, io_uring, TCP/UDP dials to IPv4/IPv6 loopback and a documentation-range LAN destination, custom-resolver DNS and HTTP without proxies. It requires socket permission denial, not merely an unreachable destination. DNS's underlying resolver dial errors are checked directly because `net.DNSError` does not preserve every wrapped errno.

A test-only Linux/amd64 ptrace parent exercises the compiled startup defenses without changing production code: it changes the result of an actually denied IP socket into harmless fd0, and separately changes a successful `PR_SET_NO_NEW_PRIVS` result into `EPERM`. Both produce the expected fail-closed startup error. No IP socket is opened by this substitution. The helper writes real Go raw coverage counters into the test coverage directory; the tracer never fabricates counters. A platform that blocks ptrace reports the test **BLOCKED**, so it cannot silently meet the floor through a skipped scenario.

# Wallet actions, Settings journal and overview balances

The current owner instruction removes encrypted portable backup creation/verification entirely from the application workflow. New setup enters an app password, shows the generated BIP39 phrase in the native Go signer, asks the user to record it and confirms requested words. Phrase confirmation enables receiving and sending on all profiles. A fresh installation offers **Restore from recovery phrase**, with secret inputs confined to Go. The app password encrypts local storage and does not derive wallet addresses; an explicitly used BIP39 passphrase remains a separate recovery requirement.

Send opens its form even while phrase setup is incomplete, with a clear **Finish recovery phrase setup** action and gated preparation. Receive offers that native setup action before its authoritative QR window. Only successful confirmation for the original unchanged wallet/view/session continues to Receive. Cancelled or incomplete setup, navigation, closing and lock never resume abandoned requests. Confirmed wallets no longer need setup after password changes or additional-account metadata refreshes. Electron receives neither generated phrases nor imported credentials.

The Local payment journal belongs in Settings, with independent wallet and asset selectors. Inspecting another journal cannot switch the active wallet, rewrite a Send draft or release its reservation. Cancellation remains limited to the original unsigned PREPARED operation; reconciliation uses its original identity. Context changes discard stale results/errors rather than applying them to the current form.

The overview shows each wallet's registered native-currency balance: ETH on Base/Horizen, separate HYPE domains on HyperEVM/Core and the relevant native asset elsewhere. Amounts use exact atomic decimal strings. Missing, malformed, incomplete and failed observations stay unknown/unavailable. Provider observations are not consensus proofs. Queries disclose public addresses, run once per visible descriptor with one background request at a time and stop scheduling on lock. Native actions pause new background work until metadata refresh completes; a query already running can delay a queued native action up to its backend deadline. No automatic payment retry follows.

## Historical diagnosis and results

The preceding interface disabled Send and Receive when a mainnet encrypted backup was unverified. Its regression expected disabled entry buttons and its packaged workflow opened Receive only after a backup; those tests missed the unusable entry experience. The later wallet-actions campaign fixed entry behavior, moved the journal to Settings and added overview balances. Its [retained report](evidence/wallet-actions.json) passed 65 frontend tests and 27 checks on that artifact, including native QR decoding and clipboard comparison. Its Go code was unchanged from the preceding source-bound coverage campaign. Those results do not certify the newly changed Go/native phrase setup or current desktop artifact.

Historical exploratory driver attempts remain failures: OCR stopped after five checks, and a preceding 64-test artifact stopped after twenty-four while awaiting Account 2. Fresh runs against that historical final artifact passed twenty-seven checks. None of those file-backup scenarios are treated as a current written-phrase recovery drill. The earlier table/tab campaign is retained in [WALLET_LAYOUT.md](WALLET_LAYOUT.md); current release limits remain in [STATUS.md](STATUS.md).

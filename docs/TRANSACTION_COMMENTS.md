# Blockchain transaction comments

The NEAR staking text headed Network / Account / Staking pool contract / Method / Attached NEAR / Gas / Planned effect is generated for local dialogs. It was incorrectly reused as the Comment cell of a local history row. The signer never serialized that prose: `deposit_and_stake` signs literal `{}` arguments, the exact attached deposit and fixed gas, with the normal NEAR transaction fields and signature. Contract, method, amount and gas are public chain data, but this formatted explanation is not a transaction memo. A bounded public read-only lookup also found the reported matching 1.5 NEAR staking transaction and independently checked its sole action through the chain-identified mainnet RPC: `{}` arguments, exact deposit/gas, FINAL success and a complete successful six-receipt graph. This is an RPC observation, not an independent consensus proof. Identifying account/transaction data stays in the ignored local report.

The history Comment column now comes only from decoded chain transfer effects. Missing comments and local-only operations display **—**. A saved draft memo cannot fill an empty observed memo. This presentation change does not erase saved intent, alter signed bytes, change reconciliation or add a new transaction. Detailed staking operation summaries remain in approval and pending-operation dialogs.

The same rule removes generated NEAR attached-deposit method labels, NEP-141 mint/burn prefixes, Aptos missing-peer explanations and the retired Decred coinbase label. Real NEP-141 event memo fields and TON native/jetton plaintext comments are preserved exactly, including whitespace, Unicode and text that resembles a UI label. Unknown counterparties remain unknown; amounts, directions, statuses and supported assets are retained.
